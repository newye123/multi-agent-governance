# 派工决策树

七棵树，覆盖从「要不要派」到「什么时候该停手上报」的整条链路。
每棵树的叶子都是**一个可执行动作**，不是一句原则。

---

## 树 0：要不要派

```
这个活必须派出去吗？
├─ 我能在这个轮次内做完，且不需要第二只手判定质量
│     └─ 不派。自己做完，但留一条可复跑的判据给下一个人
├─ 需要第二只手判定质量（写的人不能自己批）
│     └─ 派。进树 1
├─ 活很长（跨夜 / 多步骤 / 超过一个上下文窗口）
│     └─ 派 chat 会话。进树 2
└─ 只是「想并行加速」
      └─ 先问：这两份活写的是同一批文件吗？
            ├─ 是 → 不派。并行会撞，收益是负的
            └─ 否 → 派。进树 1
```

**为什么「只是加速」要拦一道**：并行的成本不是零。多一个写者，就多一次撞车检测、
多一份回包要复验、多一个槽要回收。写入面相交时，这些成本远大于省下的时间。

## 树 1：派给谁（按写入面，不按话题）

```
这个任务要改哪些路径？
├─ 服务端 / 账务 / 计费 / 结算 / 迁移      → 户部槽
├─ 门禁 / 测试 / 守卫断言 / 预检            → 刑部槽
├─ 取证 / 度量 / 普查 / 读数工具            → 工部槽
├─ 打包 / 签名 / 预检 / 部署上站            → 兵部槽
├─ 前端 / 界面 / 对外文案                   → 礼部槽
├─ 规范文档 / 记录 / 接力指针               → 吏部槽
└─ 跨两个以上写入面
      └─ 拆成两个任务，分别派。不要派给「一个什么都能干的槽」
```

**判据是写入面，不是话题。**

「这个改动既碰前端又碰门禁」——按话题看是一个任务，按写入面看是两个。
按话题派，两个槽必然撞同一批文件；按写入面派，撞车在派工那一刻就暴露了。

拆的时候注意：拆出来的两个任务**必须能独立验收**。
如果 B 必须等 A 的产物才能开始，那不是并行，是串行，应该合成一个任务派。

## 树 2：派 chat 会话还是 Agent

```
这个活的预期时长？
├─ 几分钟，且只读（普查、读数、单次核验）
│     └─ 可以用 Agent
├─ 超过几分钟，或需要写文件
│     └─ 派 chat 会话。**不要派 Agent**
└─ 跨夜 / 多步骤 / 需要中途做判断
      └─ 派 chat 会话，且把判断依据全部写进任务书
```

理由不是偏好，是实测：**后台 Agent 会被「用户插一句话」连带杀死，且不发完成通知。**

用户插一句话是完全正常的行为，不是误操作。但后果是：跑到一半的 Agent 连人带现场一起没了，
盘上只剩两个已改未提交的文件，而**没有任何一方收到通知**——包括派它的那只手。

判断「能不能用 Agent」的真正问题不是「活大不大」，是：

> **如果它中途消失，我多久会知道？**

答案如果是「等我想起来去问」，那就不能用 Agent。

## 树 3：超编了怎么办

```
当前 在任 + 空置 >= 8？
├─ 否 → 直接新建，登记写入面
└─ 是 → 按「末次活跃」升序排列
         ├─ 存在「空置」槽 → 解任最老的空置槽，腾位后新建
         └─ 全部在任
               ├─ 新任务更紧急 → 停车，向 Owner 说明「需扩编」及有效期
               └─ 否则 → 排队。**不超编**
```

两条反直觉的：

1. **解任的是「最老的空闲槽」，不是「最老的槽」。** 最老的槽很可能正在干最关键的活。
2. **「空置」和「已解任」不是一回事。** 往已解任的槽里塞新活，它会带着上一轮的
   上下文和结论去干新活，而你不知道它带了什么。宁可新建。

超编不是效率问题，是**可观测性问题**：槽一多，就没人能说出「现在到底有几个活在跑」。

## 树 4：收包了，判绿还是判红

```
回包里有结论吗（≤5 行）？
├─ 没有 → 驳回。不合格回包
└─ 有 → 逐条核锚点
      ├─ 每条论断都有 file:line 或 命令+退出码？
      │     ├─ 没有 → 驳回（封驳理由：锚点造假）
      │     └─ 有 → 进下一步
      ├─ 我自己独立复跑过门禁命令吗？
      │     ├─ 没有 → **现在跑**。不复跑不算复验
      │     └─ 跑了 → 退出码与我拿到的一致吗？
      │           ├─ 不一致 → 驳回（退出码造假），附我的实测原式
      │           └─ 一致 → 进下一步
      ├─ git status / git show --stat 只落在授权写入面内？
      │     ├─ 否 → 驳回（写入面越界）
      │     └─ 是 → 进下一步
      ├─ 产物长在任务书声明的那个 SHA 上？
      │     ├─ 否 → 整包作废（基线错）。不「顺手改改」
      │     └─ 是 → 进下一步
      └─ 结论与能力现状表冲突吗？
            ├─ 冲突 → 驳回，且**同时要求更新对应行**（附变更 SHA 与核验日期）
            └─ 不冲突 → 记账，槽位置「已解任」
```

### 封驳理由只认五类

```
基线错 ／ 写入面越界 ／ 退出码或锚点造假 ／ 判据未满足 ／ 与权威清单冲突且未实测
```

不在这五类里的，**一律「放行 + 记开放问题」**。
这条限制是给复验手自己设的——否则门下会慢慢变成第二个执行者，开始提「你应该这样改」。

## 树 5：回包说「红」了

```
红的性质是什么？
├─ 判据没满足（测试真失败）→ 正常驳回，重派
├─ 命令跑不起来（脚本不存在 / 参数错 / 环境缺依赖）
│     └─ **先核判据本身**：这条命令存在吗？空跑一次
│           ├─ 不存在 → 判据错，**记总控，不记执行手**，重写任务书
│           └─ 存在 → 环境问题，记开放问题，不算执行手的错
└─ 不确定
      └─ 不许当红处理。当「未核实」处理，写进回包待定
```

最后一条很重要：**「不确定」不是一个可以凑合的状态。**
把不确定当红，会白重派一轮；把不确定当绿，会污染账本。两个都错，只能标 `unverified`。

## 树 6：现场异常

```
巡检发现异常
├─ porcelain 非空，且不是我造成的
│     ├─ 是「应用→跑→还原」的中间态 → 两拍后再看，别急着判脏
│     └─ 稳定存在 → 有并发写者。**停止一切写入**，先搞清是谁
├─ 台账莫名少了几行
│     └─ 查 birth（不是 mtime）。birth 很新 ⇒ 整册替换，见案例 03
├─ 派出去的槽无回包
│     ├─ 未超时限 → 等
│     └─ 超时限 → 判挂死，回收槽位，改派 chat 会话（现场以最近提交/补丁为准）
└─ 两个槽在改同一批文件
      └─ 立即停一个。**不要「让他们协调」**——他们互相看不见
```

## 树 7：什么时候该停手

```
连续被驳回的轮次？
├─ 1–3 轮 → 重派，同一槽，附上具体的驳回理由
├─ 第 4 轮 → 换新槽（换人）+ 升级表述（把「没做到」改成「这条判据到底要求什么」）
└─ 第 4 轮仍不合格
      └─ **停车，上报 Owner**。不再自动重派
```

停手的信号还有三个，出现任一个就该停：

1. **判据本身可能是错的**（已经换了两只手都做不到，大概率不是手的问题）
2. **需要一个人来拍板**（技术上无解，是取舍问题）
3. **红线动作**（部署生产、翻闸、支付开关、删档）

第 3 类**永远**先问，不因为「证据充分」就跳过。
证据充分只能证明「技术上可行」，不能证明「现在该做」。

## 一页流程图

```
要不要派 ──否──→ 自己做 + 留判据
   │是
   ↓
写入面相交？ ──是──→ 串行 / 换树（不并行）
   │否
   ↓
按写入面选槽 ──→ 有匹配空槽？ ──否──→ 未超编？ ──否──→ 排队
   │是                              │是
   ↓                                 ↓
复用                            新建
   └──────────┬─────────────────────┘
              ↓
      任务书八字段一次写全
              ↓
      门下自检（基线三问）
              ↓
           派出（只一次）
              ↓
        有回包文件？ ──否（超时）──→ 判挂死 → 回收 → 改派 chat
              │是
              ↓
      另一只手独立复跑 + 七项
         │            │
        红            绿
         │            │
      五类理由驳回   记账 + 解任
         │
      同槽 ≤3 轮 → 第 4 轮换人 → 仍不合格 → 停车上报
```
